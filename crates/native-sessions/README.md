# Durable encrypted native records

`SessionStore::open(path, Arc<VaultService>)` creates a SQLite native record database under the drive's sessions directory. Message bodies, configuration, complete provider messages/tool metadata, pending arguments, checkpoints and workspace memory use XChaCha20-Poly1305 with random nonces and record identity/version AAD. Only opaque IDs and lifecycle state are plaintext SQL metadata.

A random 256-bit record key is generated once while the existing vault is unlocked, stored there under `native-record-encryption-key`, and resolved through short-lived `process:native-record-store` handles. Handles are revoked per operation. No plaintext config key or long-lived decrypted key cache is used. Locked/missing/damaged vaults make private records unavailable; list/status expose only IDs/status. Authenticated decryption failures never produce an empty or plaintext history.

SQLite transactions commit each encrypted record and its run metadata together. Message command IDs bind to input hashes and return the original run when repeated; changed-input reuse fails. Startup interrupts active runs, and private state reconciles with that metadata after unlock. Native execution owns continuation and never repeats pending effects without fresh user action/planning.

The old process-local `SessionCatalog` remains exported for compatibility. It is separate from the durable native service. Independent cryptographic review and whole-database rollback detection remain release-security concerns, as with the existing vault.

## Artifacts

Native sessions own artifacts (`document`, `code`, `data`, `diagram`, `plan`, `web_page`, `other`): `create_artifact(session_id, run_id, NewArtifact { name, kind, mime, language, bytes })`, `list_artifacts(session_id, offset, limit)` (newest first, 1-100 per page), `artifact(id)`, `read_artifact(id, offset, limit)` (pages of at most 64 KiB), `update_artifact(id, bytes)`, `delete_artifact(id)`, and `set_plan_status(id, status)`. A run id must belong to the session.

- **Storage.** The `artifacts` table is created with `IF NOT EXISTS` on open, so daemons that predate it keep opening the same database and never read it. Only the artifact id, the session id and, for blobs, a content address are plaintext columns; `ArtifactMeta` (name, kind, MIME type, language, size, plaintext SHA-256, encoding, plan status, times) is sealed with AAD `aidex-native-v1:artifact:<id>:<session>`. Artifacts are unavailable while the vault is locked, like session history, and deleting a session deletes its artifacts. Rows left by a session that an older daemon deleted are dropped when the store opens (their blobs are then swept), and an artifact whose session is gone reads as not found.
- **Bytes.** Content is sealed in independently authenticated 64 KiB segments whose AAD binds the artifact id, the plaintext SHA-256, the segment index and the segment count, so a paged read decrypts at most two segments and segments cannot be moved, dropped or mixed across artifacts or revisions. Up to 1 MiB is stored inline in the row; larger content (at most 16 MiB) goes to `<db stem>-artifacts/<sha256 of the sealed file>` beside the database (`private/sessions/native-artifacts/` on a drive). Blob files are synced and renamed into place before their row commits; replaced or deleted blobs are removed after commit, and unreferenced blobs and temporary files are swept when the store opens.
- **Encoding.** Content that is valid UTF-8 reads as `utf8`, and its pages start and end on character boundaries (a page always makes progress); anything else reads as `base64` in the daemon's `artifact.read`.
- **Plans.** A `plan` artifact starts `active` and supersedes the session's previous active plan in the same transaction; `set_plan_status` marks a plan `completed` or `superseded`, or makes it `active` again (superseding the other one). Other kinds have no plan status.
- **Limits and validation.** Names are 1-256 bytes without control characters, MIME types are `type/subtype` (parameters are dropped, lowercased), languages are 1-32 bytes of `[a-z0-9+#._-]`. `NewArtifact` and `ArtifactChunk` print byte counts, never content, in `Debug`.
