# aidex-bundle

The portable bundle contract shared by the packager, the drive-root launcher, and the updater (`aidex-updater`): the closed-schema `bundle.json` manifest, its detached Ed25519 signature `bundle.sig` and the trust store that accepts it, the drive's atomic `app/current.json` pointer, the update journal `app/update-journal.json`, integrity verification, deterministic archives, and crash-safe installation onto an initialized drive. Schemas, layout, launcher behaviour, and limits are specified in [`portable/packaging/README.md`](../../portable/packaging/README.md).

## API

- `Target` (`windows-x64`, `linux-x64`, `linux-arm64`, `macos-arm64`, `macos-x64`; serde/`FromStr` use these names): `host()`, `executable_name(stem)`, `default_rust_triple()`.
- `BundleManifest { schema_version, product, version, git_commit, source_dirty, target, rust_target, rustc, created_at, min_drive_schema, state: StatePaths, files: Vec<BundleFile>, licenses: Vec<LicenseEntry> }` with `from_json(&[u8])`, `to_json()`, `validate()`, `normalize()`, `file(FileRole)`, `find(path)`, `critical_files()`. `BundleFile { path, sha256, size, executable, role }` and `BundleFile::describe(bundle_dir, path, role, executable)`; `FileRole::{Launcher, Cli, Daemon, Helper, Desktop, Installer, Runtime, Doc}` with `is_critical()`; `LicenseEntry { component, version, spdx, source, path }`; `StatePaths { drive_manifest, runtime_state, layout, host_extraction }` and `StatePaths::current()`.
- `CurrentPointer { schema_version, targets: BTreeMap<String, TargetPointer> }`, `TargetPointer { version, dir, manifest_sha256, previous: Option<VersionRef> }`, `VersionRef { version, dir, manifest_sha256 }`: `load(path) -> Result<Option<_>>`, `store(path)` (temporary file + fsync + rename), `get(Target)`, `switch(Target, VersionRef)` (the old entry becomes `previous`), `installed_targets()`.
- `verify_bundle(dir, VerifyScope::{Critical, All}) -> VerifiedBundle { dir, manifest, manifest_sha256, scope, verified_files }`, `read_manifest(dir)`, `read_manifest_bytes(dir)`.
- `resolve_active(&DrivePaths, Target, VerifyScope, &SignaturePolicy) -> ActiveBundle { target, pointer, bundle, signature: SignatureState }`: pointer → pinned manifest → target/version/drive-schema checks → signature → file verification. This is exactly what the launcher runs before executing anything.
- Signatures: `BundleSignature` (`bundle.sig`, schema 1: `algorithm: ed25519`, `key_id`, `manifest_sha256`, `signature`), `sign_manifest(bytes, &KeyPair)`, `signed_message(bytes)` (= `SIGNATURE_CONTEXT` `AIDEX-BUNDLE-SIG-V1\n` + the exact `bundle.json` bytes), `read_signature`, `write_signature`, `verify_signature(dir, bytes, created_at, &SignaturePolicy) -> SignatureState::{Verified { key_id, key_name, key_source }, UnsignedAllowed}`. `SignaturePolicy { trust, allow_unsigned }` (`require`, `allow_unsigned`).
- Trust: `TrustStore::{empty, builtin, with_key, add_key, revoke, with_drive_revocations, keys, key, revocations, verify, dev_trust_enabled}`, `TrustedKey::{new, with_validity, key_id, name, source, not_before, not_after}`, `KeySource::{Release, Build, Development, Explicit}`, `Revocation`, `RevocationList` (`manifests/revoked-keys.json`, `revocations_path`), `KeyPair::{generate, load_secret, store_secret, public_file, sign, trusted_key}`, `PublicKeyFile`, `SigningKeyFile` (redacted `Debug`), `key_id_for(public key)` (first 8 bytes of its SHA-256, hex). `builtin()` = compiled-in `src/signature/release-keys.json` + compile-time `AIDEX_BUILD_TRUSTED_KEYS` + run-time `AIDEX_DEV_TRUSTED_KEYS` only with the `dev-trust` feature (enabled by dev-dependencies, so only in test builds).
- Journal: `UpdateJournal { id, operation: JournalOperation::{Apply, Rollback}, target, state: JournalState::{Staging, Verified, SelfTest, Switching, Committed, Aborted}, started_at, updated_at, staging, before: Option<CurrentPointer>, candidate_version, to: Option<VersionRef>, created_version_dir, signer_key_id, outcome }` with `load`/`store` (atomic), `advance`, `finish`; `journal_path(&DrivePaths)`.
- `install(&InstallSource, drive_root)` and `install_with(.., observer: &mut dyn FnMut(InstallStep) -> Result<(), BundleError>)` → `InstallReport { drive_root, target, version, dir, manifest_sha256, reused_existing, previous, launchers: Vec<LauncherPlacement>, signature }` check integrity only; `install_signed(source, root, &SignaturePolicy, observer)` also requires `bundle.sig` to satisfy the policy before anything is committed. `InstallSource::{Directory, Archive}` (`from_path` detects); `InstallStep::{Stage, Verify, Commit, PlaceLauncher, SwitchPointer, Cleanup}`; the observer runs before each step and can stop the install (progress, cancellation, fault-injection tests). `steps::{stage, apply_modes, preflight_launchers, place_launchers, plan_commit, execute_commit, CommitPlan}` expose the individual steps to the updater.
- Crash-safe file helpers: `write_atomic`, `write_atomic_with(path, bytes, before_rename)` (fault injection), `stale_temporaries(dir, name)`, `sync_dir`; `CurrentPointer::store_with`.
- `LAUNCHER_MARKER`, `is_aidex_launcher(path)`, `unix_entry_script(app_relative)`; `layout::*` names and path helpers (`pointer_path`, `versions_dir`, `launcher_path`, `bin_path`, ...).
- `Sha256Sums` (`parse`, `load`, `get`, `set`, `render`, `store`) for `sha256sum`-compatible checksum files; `sha256_hex`, `sha256_file`, `is_sha256_hex`.
- Feature `archive` (packager and updater; the launcher does not enable it): `archive::{write_archive, extract_archive, ExtractLimits, ArchiveFormat, archive_file_name, bundle_root_name}`.
- `BundleError` with `kind() -> BundleErrorKind::{Drive, NotInstalled, Incompatible, Integrity, Untrusted, Occupied, InvalidInput, Aborted, Io}` and `code() -> aidex_core::ServiceErrorCode`; `DocumentError::{UnsupportedSchema, Malformed, Invalid}`; `IntegrityProblem::{Missing, NotRegularFile, Link, SizeMismatch, DigestMismatch, Unlisted, ManifestPin}`; `SignatureError::{Unsigned, Malformed, ManifestMismatch, UnknownKey, RevokedKey, KeyNotValid, BadSignature}` with a stable `reason()`; typed archive refusals `ArchiveEntry { name, reason }` (traversal, absolute, link, device, duplicate, outside the root) and `ArchiveLimit`.

## Guarantees

- Manifests and pointers are closed schemas; a different `schema_version` is reported as unsupported before any field is interpreted. Paths are portable across NTFS/exFAT/FAT32/ext4/APFS, unique case-insensitively, and cannot escape the bundle; pointer directories cannot escape `app/versions/`.
- Verification refuses symbolic links and junctions anywhere on a file's path, size or SHA-256 mismatches, missing files, and unlisted files (in `bin/` for the critical scope; anywhere for the full scope; `bundle.json` and `bundle.sig` at the top are the only unlisted names allowed). `resolve_active` compares `bundle.json` with its pinned digest before parsing it and checks the signature before hashing files.
- A signature is accepted only from a trusted key that is not revoked (revocation wins over trust) and whose validity window contains the bundle's `created_at`, and only if it verifies (`verify_strict`) over the exact manifest bytes. `allow_unsigned` accepts a *missing* signature only; a present but invalid, unknown, or revoked one is always refused. Secret keys are zeroized after use and never appear in `Debug` output; key files are created exclusively (0600 on Unix).
- Installation stages on the drive, verifies everything before committing, never modifies a committed version directory, replaces only files carrying the launcher marker (keeping `<name>.previous`), and leaves `app/current.json` untouched until the final atomic switch. Every interruption point is covered by tests.
- Archive writing is deterministic; extraction accepts only regular files and directories under one top-level directory, with entry-count and size limits.

## Limitations

- The trust anchor is compiled into the binaries on the drive: someone who can replace the launcher itself defeats it (see `docs/security.md`). A check-then-exec race with a concurrent writer of the drive is not prevented.
- `install`/`install_with` take no lock and do not prune; the updater adds both for updates.
- Directory fsync after renames is a no-op on Windows and best effort on FAT-family filesystems.
- Unix modes are applied from the manifest; on filesystems without permission bits (FAT, exFAT) the mount options decide executability.
