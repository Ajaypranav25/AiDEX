# Native execution

`NativeEngine` composes the encrypted `SessionStore`, real `ProviderRegistry`, selected `WorkspaceRegistry`, typed tool registry and `aidex-policy` with sandbox-managed process trees. Agent turns offer confined read/list/search/write/patch, Git and shell functions, plus bounded `agent_spawn`/`agent_result` child execution. `NativeEngine::with_extensions` adds the embedder's skills, web search and fetch, and MCP servers (`Extensions`; the daemon implements it in `crates/aidexd/src/services/extensions.rs`).

## Skills, web, MCP, artifacts, and plans

- **Invoked skills.** `start_with(..., RunOptions { skills, web_search })` takes at most eight skill ids (`<scope>:<name>`); unknown, disabled, or not user-invocable ids fail with an error starting `skill_unavailable:` before any run is created. Each invoked skill reaches the model as a system message for that run only: `The user invoked the skill "<name>". Follow its instructions for this request.` followed by the body between nonce delimiters (`trust=user` for drive skills, `trust=project` otherwise). The stored user message keeps the text exactly as typed; the ids are recorded on the run (`Run.skills`, `Run.message_index`; `Run` has no `deny_unknown_fields`, so older daemons ignore them). External runtimes receive the text unchanged and ignore both options.
- **Which tools a turn offers.** Agent: the workspace tools, child tools, artifacts, `skill_load`, MCP tools, and the web tools when web search is enabled and configured. Plan: artifacts, `plan_propose`, `skill_load`, and the web tools when enabled (no workspace tools, no MCP). Chat: no tools, unless the request set `web_search` (an error starting `web_unavailable:` when web search is off), then the web tools, artifacts, and `skill_load`. Harness-level tools never need a workspace. Tools are offered only to models with native tool calling.
- **Stable names.** `web_search`, `web_fetch`, `skill_load`, `artifact_create`, `artifact_update`, `plan_propose` (the dotted ids with underscores) and `mcp__<server>__<tool>` (sanitised to `[A-Za-z0-9_-]{1,64}`, ordered by server id and tool name, collisions suffixed `_2`, `_3`, ...).
- **Untrusted data.** Results of `web_search`, `web_fetch`, MCP tools (`trust=untrusted`) and `skill_load` (`trust=project`) are stored as produced (JSON for web results) and wrapped between `<<<aidex:context nonce=... source=tool name="..." call="..." trust=...>>>` and `<<<aidex:end nonce=...>>>` delimiters when the prompt is assembled; delimiter text inside content is defused. The nonce is derived from a random per-engine key and the run id. A system preamble explains the delimiters, the model-invocable skill catalog is itself delimited, and web tools come with an instruction to cite source URLs.
- **Policy and approvals.** Network tools evaluate `network.request` for the provider host or fetched host under the drive's policy documents and the embedder's policy settings, after the offline switch and emergency stop (`Extensions::network`); approval verdicts refuse, like the daemon's egress gate. `web_search` and `skill_load` never ask; `web_fetch` asks in Supervised and Auto-accept-edits modes and runs in Auto and Full access. MCP calls evaluate `mcp.call` and ask unless the tool is in the server's `auto_approve_tools` or the session has Full access. Refusals and failures become tool results the model can read; a denied approval runs nothing.
- **Artifacts and plans.** `artifact_create` / `artifact_update` store encrypted artifacts of the conversation (at most 1 MiB per call; updates only within the same conversation). `plan_propose` stores a `plan` artifact that supersedes the previous active plan. `web_fetch` pages whose text exceeds 64 KiB are saved as `web_page` artifacts and only the first 64 KiB is returned.

Runs have explicit pending/running/waiting_approval/completed/failed/cancelled/interrupted states. Message command IDs are durable and bound to their inputs. Approvals bind to a sealed plan fingerprint and include the planned diff. Decisions are saved before effects and duplicate decisions do not repeat execution. Restart never replays a non-idempotent effect: it marks active runs interrupted, invalidates old executable approval plans, and requires explicit continuation.

Drive policies and workspace project rules are evaluated before invocation/planning. Workspace tool plans that reach the network (`git.push`, a command classified as networked) are refused while the offline switch or an emergency stop is on, and their intents are evaluated with the drive's privacy, host-trust, and network-mode settings (the profile still follows the permission mode), so local-only, air-gapped, offline, and allowlist floors apply. Policy changes invalidate existing tool plans. Model invocation/child creation that needs a policy approval or rate-limit gate currently fails closed; tool approvals are implemented. Tool arguments and outputs, messages, instructions, checkpoints and memory remain encrypted in the session database. Durable events contain metadata; live text deltas are ephemeral and assistant text is coalesced into encrypted history.

Selected provider/model capabilities and output limits are checked against a listing of the run's own provider only (`ProviderRegistry::models_for`, which reuses fresh cached listings); a disabled account is refused as unavailable, and a failed listing reports that provider's error. External runtimes ignore the session's provider (runtime sessions record the placeholder `runtime`), and the model id `default` (`RUNTIME_DEFAULT_MODEL`) is sent as no model so the runtime uses its own default. One explicitly configured `provider/model` fallback can run after a retryable inference failure; cancelled, unauthorized, malformed or denied requests do not fall back. No tool effect is retried by fallback. The turn/operation step cap is 128 and the configured output cap is 32768 tokens; defaults are 16 steps and 4096 tokens. Children share their parent's scope, with four immediate children and depth two. Child completion never completes the root.

Windows brokered processes have cleared environments, tracked Job Object trees and watchdog limits. Filesystem and network confinement are unsupported. Supervised shell requests restricted confinement and fails closed; explicit `full_access` opts into brokered same-user execution. Hard policy restrictions still apply. `auto` has no automatic reviewer and uses supervised approvals. Ship `aidex-sandbox-exec` beside `aidexd`.

File-tool writes record encrypted before-content and expected after-digests. Restoring an existing UTF-8 file uses the atomic typed write tool and refuses conflicting user edits or active execution. File deletion/new-file removal and checkpointing arbitrary shell mutations are not implemented. Read/search/context walks are bounded; semantic/vector indexing is not implemented. Very large conversation/memory RPC pagination remains a follow-up; durable records remain on the drive.

The desktop's typed conversation/run/approval/checkpoint contracts are in `packages/client/src/dto/sessions.ts`, with RPC bindings in `packages/client/src/rpc.ts`. Tests use deterministic FakeProvider turns through the real service, plus a real Windows sandbox-helper shell process. Resuming an interrupted root appends matching tool results to both the run transcript and conversation history; later turns therefore retain complete tool-call pairs without repeating effects.
